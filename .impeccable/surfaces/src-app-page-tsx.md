# Command center and scan intake

- **Mode:** Operate, with a Persuade opening only when no saved scan exists.
- **Audience and job:** Node.js developers and application-security engineers need to scan manifests, identify the highest-risk dependency, choose a remediation, and prove the posture change.
- **Primary action:** Scan a project using reproducible `package.json` and `package-lock.json` evidence.
- **Proof:** Real persisted score, grade, dependency topology, CVE/CVSS data, remediation class, scan history, and before/after evidence.
- **Constraints:** Existing route handlers and scoring remain untouched; source uploads remain deployment-gated; Attack Replay stays fixed to localhost; no synthetic metrics; WCAG AA, keyboard support, reduced motion, and responsive stacking are required.
- **Chosen direction:** Cyber Brutalism as an Active Scan Field—composition A’s thesis/rail, composition B’s dense evidence ledger, and composition C’s functional manifest intake.
- **Memorable moment:** A sparse wireframe profile dissolves into machine telemetry, then resolves into the operator’s real dependency ledger.
- **Unresolved:** None; the supplied brief fixes palette, interaction language, component boundaries, and safety copy.
